# BUG-01 production rollout plan - review only

No deployment, production migration, financial backfill or main merge is authorized by this work. Candidate migration: 045_transfer_cost_snapshot.sql. Migration is additive; existing dispatched lines remain NULL. New application requires migration first. Snapshot 0 is valid; NULL is unknown and must not be replaced with global product price. During a mixed deployment old writers can create or receive uncosted transfers even after schema migration. A controlled writer drain/quiescence and a coordinated cutover are required, with a reviewed inventory of in-flight transfers and explicit manual-review procedures before migration or deployment.

Release gates: independent financial and concurrency review; approve in-transit, shortages, overages, negative stock, rounding residual and legacy handling; implement or explicitly accept missing create idempotency and validate timeout retries; complete outstanding browser-to-Postgres Classic/Touch/return/history/analytics and all requested error, isolation, concurrent and extreme-value cases; verify old and new clients plus independently reconcile report COGS/valuation. Run full backend and frontend checks and verify immutable snapshot migration in an isolated production-like environment. Confirm production versions, backup/restore and migration window by authorized operators.

Rollback: stop or drain writers before reverting application; reverting code without controls reintroduces lost-cost transfer and return behavior, and a legacy writer may ignore snapshots. Preserve migration column, trigger, snapshots, audit records and existing transactions; do not drop or backfill data. Any schema rollback, adjustment posting, production database write or historical correction is a separate reviewed operation requiring explicit authorization. Mixed-version rollback, in-flight transfers, audit reconciliation and customer communication need an operator-approved runbook before production changes.
