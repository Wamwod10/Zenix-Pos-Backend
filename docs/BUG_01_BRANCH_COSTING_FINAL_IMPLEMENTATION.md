# BUG-01 branch costing implementation

Status: candidate for draft review, not production-ready. Branch starts at backend main 71db18030c5abcb56190c4c7c9d6d15722cb5c5f. The user approved dispatch average cost, weighted-average receipt and original-sale-cost returns; shortage variance, overage accounting, negative balances, rounding residual and in-transit ledger remain unresolved. No production database was accessed or written.

Root cause: dispatch did not store source balance cost or movement unit cost; receipt changed only quantity; returns changed only quantity and could silently treat a missing sale cost as zero. Existing audit reported a 5 x 1000 source receipt and 2-unit transfer with zero-valued destination, sale and return movements. Historical production values were not independently queried.

Changed: migrations/045_transfer_cost_snapshot.sql adds nullable numeric(18,2) snapshot with a nonnegative check and an immutable-after-set trigger. No UPDATE/backfill. src/routes/inventory.js captures locked source avg_cost on dispatch, writes it on transfer_out and uses snapshot on receipt/cancel. Transfer lines and creation balance locks are ordered by product ID. Quantity/cost updates use PostgreSQL NUMERIC: avg_cost = ((quantity * avg_cost) + (received * snapshot)) / (quantity + received), with numeric(18,2) assignment and existing PostgreSQL rounding. Return path src/routes/sales.js obtains the tenant/store scoped original sale movement cost, or a recorded sale item metadata snapshot, never global price; missing snapshot returns SALE_COST_UNKNOWN. It restores weighted cost and return movement cost in one transaction; zero is preserved. A negative starting balance and unknown legacy transfer cost return 409; over-receipt returns 409. Short receipt is final with a difference reason; no variance income/expense is posted. Zero received retains existing average. For cancellation after dispatch, source weighted average restores the snapshot. Existing duplicate transition status checks return 409 and roll back partial writes. src/db/verifySchema.js checks migration, nullable column and trigger; tests/database-production.test.mjs adds the new migration without deleting assertions.

Precision: quantity numeric(18,3), cost numeric(18,2). PostgreSQL stores fractional results rounded to the column scale, which can cause an inventory valuation residual; no separate residual posting is implemented. Arithmetic overflow rolls back. Existing receipt path and reports have additional JavaScript number computations not comprehensively refactored; extreme-value and overflow tests remain required.

Compatibility and risk: schema must precede new code. Old in-flight dispatched rows have NULL snapshots; receipt/cancel intentionally return 409 and require manual review. Old code running after migration can still create NULL dispatch snapshots or receive at old cost. Avoid mixed-writer deployments by draining/quiescing old writers and reviewing in-flight transfers before cutover. The response change is additive and retains existing keys, but full old/new client matrix is not proven. Transfer-create API has no stable idempotency reference: a retry after an unknown create response can create a second transfer. Duplicate dispatch/receive/cancel on the same ID are prevented, but that is not create idempotency. Do not claim exactly-once create. Lock ordering is improved but cross-operation deadlock freedom is not proven.

Tests, quantified evidence and untested cases: BUG_01_COSTING_RECONCILIATION_RESULTS.md. Rollout, rollback and gates: BUG_01_PRODUCTION_ROLLOUT_PLAN.md. Browser and database checks were performed solely on a local disposable database.
